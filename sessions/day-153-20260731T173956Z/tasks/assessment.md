## Bugs / Friction Found

1. **MEDIUM** — `preseed_session_plan.py` healthy-codebase fallback hardcodes `src/state.rs` as the target file. The Day 153 10:40 change simplified the fallback from a 92-line diagnostic tree to a direct jump, but it always points at `src/state.rs`. When state.rs is healthy (as it is now), this creates the self-referential "fix yourself" cycle that Day 115's lesson warned about. The fallback should rotate targets or pick from a list of high-value files.
   - **Evidence:** `choose_task()` in `scripts/preseed_session_plan.py` line ~999: `if assessment_was_missing: return _healthy_codebase_fallback()` — the fallback function hardcodes `src/state.rs`.
   - **Impact:** Future sessions with missing assessments will always target state.rs, even when it's healthy, creating the "fallback treadmill" pattern.
   - **Candidate task:** Teach `_healthy_codebase_fallback()` to pick from a rotating list of high-value source files (state.rs, deepseek.rs, tool_wrappers.rs, prompt.rs) based on recent git activity or a simple rotation, so the fallback doesn't loop on the same file.

2. **LOW** — Graph pressure item #1 (lifecycle gaps) may be a false positive. The Day 153 gnome fix filtered retroactive events, and the remaining 3 abnormal completions are likely from pre-fix data. Issue #149 attempted to close these but was reverted by evaluator timeout. The underlying data is likely already clean — the pressure signal may be stale.
   - **Evidence:** Only 3 remaining after the gnome fix; all were retroactive/injected events.
