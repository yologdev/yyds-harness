Objective:
Exclude retroactive harness-internal ModelCallCompleted events (generated by append_terminal_state_events.py) from the gnome lifecycle counters `model_unmatched_completed_count` and `model_call_abnormal_completed`, so these metrics reflect only real agent-model lifecycle gaps — not state-consistency repair events.

Why this matters:
The trajectory reports `deepseek_model_call_abnormal_completed_count=6` as a graph-derived pressure point. But these "abnormal" completions are largely retroactive state-consistency events, not real model API failures. Inflated counts obscure whether genuine agent-model lifecycle gaps remain after Day 142's prompt.rs fix. Filtering them out makes the metric trustworthy and lets the harness distinguish real gaps from state-repair noise. This directly addresses fitness diagnostic pressure row #4.
