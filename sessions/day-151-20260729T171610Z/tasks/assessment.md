## Upstream Dependency Signals

- **Issue #90 (yoagent)**: `Usage` struct drops DeepSeek-specific cache fields (`cache_read_input_tokens`, `cache_creation_input_tokens`). This is a yoagent upstream issue — yyds cannot fix it without either a yoagent PR or a yyds-side workaround that parses raw response JSON before yoagent processes it. The diagnostic paths (`stream-check`, `fim-complete`) already do this successfully for non-agent paths. An agent-chat-completion workaround following the same pattern would unblock cache observability without waiting for upstream.
- **Issue #131 (evolve.sh)**: Evaluator timeouts in `scripts/evolve.sh` cause false task reverts. `evolve.sh` is in yyds's do-not-modify list, so this needs human intervention. However, the pattern could be mitigated by making the evaluator more efficient (faster verdicts) or by teaching `log_feedback.py` to recognize timeout-on-passing-code as distinct from real failures.

## Capability Gaps

- **vs Claude Code**: yyds has no multi-file editing with preview, no diff-view of pending changes, no "apply and revert" workflow. The tool set is comparable but the UX polish is missing.
- **DeepSeek-specific**: Cache metrics are blind for the primary execution path (Issue #90). Prompt layout determinism work has no way to measure its own effectiveness.
- **Planning reliability**: The planner frequently produces zero tasks (planner_no_task_count recurring). When the codebase is healthy, the planner cannot distinguish "nothing needs doing" from "I failed to plan."
- **Evaluator reliability**: Evaluator timeouts (Issue #131) cause correct code to be reverted, creating a false signal of failure.

4. **[MEDIUM] Model lifecycle gap (21 unmatched completions)** — Even after Day 150's input-validation fix, 8 genuine "completion without start" events remain. This indicates a real state recording gap in how model calls are tracked.
